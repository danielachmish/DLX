# DLX: תפעול, אירוח והמשכיות

## סביבה (D15)

| רכיב | ייצור (מומלץ) | פיתוח |
|---|---|---|
| שרת API | Node 22, קונטיינר (2 עותקים לפחות) מאחורי Load Balancer עם TLS | `pnpm dev:api` |
| מסד נתונים | PostgreSQL 16 מנוהל (ענן ישראלי או אירופי), Multi-AZ, PITR | Postgres מקומי, `scripts/db-setup.sh` |
| ממשק | קבצים סטטיים (CDN), PWA | `pnpm dev:web` (Vite, proxy ל-API) |
| סודות | מנהל סודות (לא בקבצים): `JWT_SECRET`, סיסמאות DB, מפתחות ספקים | `.env` מקומי |

### תפקידי DB
- `dlx_owner`: בעלים, מריץ מיגרציות. מוגדר BYPASSRLS כדי שפונקציות `SECURITY DEFINER` (כניסה, קישור ציבורי) יעבדו. **השרת לא משתמש בו.**
- `dlx_app`: השרת. בלי BYPASSRLS ובלי TRUNCATE. כל שאילתה עוברת דרך `withTenant`.

## ניטור (NFR-09, ADM-03)
- `GET /health` לבדיקת חיות.
- מרכז החריגים (`GET /v1/reports/exceptions`): תשלומים שנתקעו, מכירות פתוחות, מסמכים בלי מספר הקצאה, פערי קופה, מלאי שלילי, פתיחות מגירה.
- `outbox_events` ממתינים לפרסום: אינדיקציה לתקלה באינטגרציה.
- יומן ביקורת: `GET /v1/audit/verify` (שלמות השרשרת). כדאי להריץ אותו יומית.

## תקלה בזמן מסחר (O-09)
1. **אין חיבור בחנות:** הקופה ממשיכה בחיפוש, סריקה ועגלה. העגלה נשמרת במכשיר. **אין סגירת מכירה ואין הפקת מסמך** (D08). ללקוח שחייב לשלם עכשיו: מסוף אשראי עצמאי + השלמת המסמך כשהחיבור חוזר (נוהל ידני, לאשר מול רו"ח).
2. **ספק הסליקה לא עונה:** התשלום נשאר `pending`, אין חיוב כפול. "בדיקת סטטוס" במרכז החריגים.
3. **שע"מ לא זמין:** חשבונית מעל הסף נחסמת. הפקה בלי מספר רק בהחלטה מקצועית (`allowWithoutAllocation`).
4. **שרת למטה:** דף סטטוס + הודעה ללקוחות. מטרה: חזרה תוך RTO.

## עדכון גרסה (ADM-04)
- מיגרציה רק קדימה, בטרנזקציה (`apps/api/src/migrate.ts`). לפני כל גרסה: גיבוי, הרצה בסביבת בדיקה, ותוכנית חזרה.
- שינוי חקיקה (שיעור, סף) = שורה חדשה בטבלה עם תאריך תחולה ב-`packages/core/src/rules.ts`. שורות קיימות לא נוגעים.
- גרסה שמשנה מסמכים או מבנה אחיד: עדכון רישום ברשות המסים (REG-04).
