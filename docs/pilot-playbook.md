# DLX: תוכנית פיילוט אצל הלקוח הראשון

**שיטה:** פיילוט "צל". DLX עובד מלא בחנות (קופה, מלאי, רכש, ספירות, דוחות), אבל **המסמך הרשמי ללקוח יוצא מהמערכת הקיימת**, עד שהתוכנה תירשם ברשות המסים. כל מסמך של DLX מודפס כ"פיילוט — לא מסמך רשמי". המערכת אוכפת את זה: אי אפשר לעבור לרשמי בלי מספר רישום.

## שלב 0: לפני שמגיעים (שבוע)

- [ ] הסכם פיילוט חתום (טיוטה: [legal/pilot-agreement.md](legal/pilot-agreement.md), לבדיקת עו"ד)
- [ ] הסכם עיבוד מידע חתום ([legal/dpa.md](legal/dpa.md))
- [ ] שרת מותקן ([deploy.md](deploy.md)), בדיקת עשן עברה, תרגול שחזור עבר
- [ ] מהלקוח: ייצוא מוצרים (מק"ט, שם, מחיר, עלות, ברקוד, קטגוריה), לקוחות עם יתרות, ספקים
- [ ] רשימת ציוד: מחשב / טאבלט / אייפד, סורק, מדפסת קבלות, מגירה. **אייפד:** צריך מדפסת רשת, או להדפיס מטאבלט אנדרואיד / מחשב
- [ ] להחליט עם הלקוח: איך מקבלים כרטיסי אשראי (המסוף הקיים של החנות + הקלדת מספר אישור ב-DLX)
- [ ] להגדיר מדדי הצלחה (למטה) ותאריך סיום

## שלב 1: הקמה (יום 1, בחנות או מרחוק)

1. פתיחת העסק ("עסק חדש"): שם, ע.מ., סוג עוסק, כתובת.
2. **הגדרות ← העסק:** מדיניות החזרה (מודפסת על הקבלה), שורת תודה, ימי החזרה.
3. **הגדרות ← סניפים וקופות:** סניף וקופה לכל עמדה.
4. **הגדרות ← עובדים:** מנהל עם אימייל וסיסמה. לכל קופאי PIN משלו (4–8 ספרות, לא משותף).
5. **מוצרים ← ייבוא:** קובץ CSV (תבנית: [templates/products.csv](templates/products.csv)), קודם "בדיקת הקובץ" ואז ייבוא. עמודת `stock` = מלאי פתיחה.
6. **לקוחות ← ייבוא:** תבנית [templates/customers.csv](templates/customers.csv). עמודת `balance` = יתרת חוב ביום המעבר. **להשוות את סך היתרות לדוח של המערכת הקודמת.**
7. **רכש ← ספקים:** ספקים עיקריים, כולל תוקף אישור ניכוי במקור.
8. **מלאי ← ספירות:** ספירת פתיחה מלאה, או בדיקה מדגמית של מלאי הפתיחה מהקובץ.
9. **הגדרות ← פיילוט ומסמכים ← יצירת סביבת תרגול.**
10. בכל מכשיר: **הגדרות ← המכשיר הזה:** לבחור את הקופה. באייפד/אייפון: שיתוף ← "הוספה למסך הבית" (בלי זה ספארי מוחק נתונים מקומיים אחרי 7 ימים).
11. בדיקת ציוד: סריקה, הדפסת קבלה 80mm, פתיחת מגירה, מכירה במסוף חיצוני.

## שלב 2: הדרכה (יום 1–2, שעה–שעתיים)

בסביבת התרגול (קוד עסק `<קוד>-train`, אותו PIN). כל קופאי עושה לפחות פעם אחת:

| תרגיל | איפה |
|---|---|
| פתיחת משמרת עם קופה קטנה | קופה |
| מכירה בסריקה, שינוי כמות, הסרת שורה | קופה |
| מוצר שקיל, מוצר עם פיקדון | קופה |
| הנחה בתוך ההרשאה, והנחה שדורשת PIN של מנהל | קופה |
| תשלום מפוצל: חלק במזומן וחלק באשראי (מסוף חיצוני + מספר אישור) | קופה ← לתשלום |
| מכירה ללקוח רשום / הקפה | קופה ← לקוח |
| מוצר מגיל 18 (בדיקת תעודה) | קופה |
| הדפסה חוזרת (מסומנת "העתק") ושליחת קישור בוואטסאפ | מסמכים |
| החזרה חלקית, החזר לאשראי / שובר זיכוי | החזרות |
| הוצאה מהקופה / משיכה לכספת / פתיחת מגירה בלי מכירה | משמרות |
| סגירת משמרת: ספירה, פער, הסבר, דוח Z | משמרות |

למנהל, בנוסף: קליטת סחורה מהזמנה, ספירה (גם בטלפון), התאמת מלאי, דוחות, ייצוא לרו"ח.

## שלב 3: הפעלה מקבילה (שבועות 1–4)

**כל עסקה נרשמת בשתי המערכות:** קודם במערכת הקיימת (המסמך הרשמי ללקוח), ואחריה ב-DLX. אם זה כבד מדי לקופה, אפשרות מקלה: DLX רק בעמדה אחת, או רק למלאי ולקליטות.

**כל יום (מנהל, 5 דקות):**
- [ ] סגירת משמרת בכל קופה ב-DLX. השוואת דוח Z לקופה הקיימת: מספר עסקאות, סה"כ, ופילוח מזומן / אשראי
- [ ] דוחות ← חריגים: לא אמורים להיות תשלומים תקועים או מכירות פתוחות
- [ ] לרשום פערים ושאלות ביומן הפיילוט

**כל שבוע:**
- [ ] ספירה מדגמית (20–30 פריטים) ← השוואה ליתרה ב-DLX
- [ ] שיחת משוב קצרה עם הקופאים ועם המנהל
- [ ] תרגול שחזור גיבוי (או לוודא שהגיבוי הלילי מועתק החוצה)

## מדדי הצלחה (להסכים מראש)

| מדד | יעד |
|---|---|
| התאמת Z יומית למערכת הקיימת | 100% מהימים, או פער מוסבר |
| דיוק מלאי בספירה מדגמית | ≥ 98% מהפריטים |
| זמן מכירה ממוצע (סריקה ← קבלה) | לא איטי יותר מהמערכת הקיימת |
| תקלות שעצרו מכירה | 0 |
| שביעות רצון קופאים / מנהל | ≥ 4 מתוך 5 |

## תקלות: מה עושים

| מצב | פעולה |
|---|---|
| אין אינטרנט | ממשיכים במערכת הקיימת. העגלה ב-DLX נשמרת, ומשלימים אחר כך |
| המסוף לא מחובר | כרגיל: מעבירים במסוף, ומקלידים ב-DLX את מספר האישור ו-4 ספרות |
| טעות במכירה שנסגרה | אין מחיקה. החזרה (זיכוי) ← מכירה חדשה |
| מלאי לא מסתדר | ספירה, ואז "התאמה" עם סיבה (מנהל) |
| משהו לא עובד | צילום מסך + מספר המסמך ← לתמיכה. מספר הבקשה מופיע בהודעת השגיאה בשרת |

## מעבר ממסמכי פיילוט למסמכים רשמיים (אחרי הפיילוט)

1. רישום התוכנה ברשות המסים + אישור רו"ח (`docs/compliance.md`).
2. מגדירים בשרת `DLX_SOFTWARE_REGISTRATION` ומפעילים מחדש.
3. בתאריך מוסכם, בסוף יום: סגירת כל המשמרות, סגירה במערכת הקודמת.
4. **הגדרות ← פיילוט ומסמכים ← מעבר למסמכים רשמיים** (רק בעלים, עם הקלדת משפט אישור).
5. מהיום הזה מפסיקים להפיק מסמכים במערכת הקודמת.
