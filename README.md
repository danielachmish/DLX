# DLX

מערכת ניהול חנות לישראל: קופה, מלאי, רכש וקליטה, לקוחות, מסמכים חשבונאיים ודוחות.
SaaS רב-עסקי, ממשק אחד שעובד בטלפון, באייפד ובמחשב (PWA).

> ⚠ **מצב פיילוט:** כל עסק נפתח במצב "פיילוט". המערכת עובדת מלא, וכל מסמך מודפס כ"פיילוט — לא מסמך רשמי". המעבר למסמכים רשמיים חסום עד שהתוכנה רשומה ברשות המסים (`DLX_SOFTWARE_REGISTRATION`), ודורש אישור בעלים. בייצור לא רצים ספקי דמה: אשראי עובר במסוף חיצוני עם מספר אישור. ר' [docs/compliance.md](docs/compliance.md).

**התקנה בשרת:** [docs/deploy.md](docs/deploy.md) · **תוכנית פיילוט:** [docs/pilot-playbook.md](docs/pilot-playbook.md)

## מבנה

```
packages/core   לוגיקה עסקית טהורה (TypeScript): כסף באגורות, מע"מ מתוארך, עגלה, תשלומים, מסמכים, מצבים, כללי ציות
apps/api        שרת Fastify + PostgreSQL (RLS לכל טבלה), API v1, מנוע מסמכים, מלאי, קופה, דוחות, ייצוא
apps/web        React + Vite (PWA), ערכת העיצוב "רך ומודרני", ניווט טלפון / אייפד / מחשב
docs/           סקירה, החלטות (D01–D16), ציות, תפעול, מערכת עיצוב
```

## הרצה מקומית

דרישות: Node 22, pnpm 10, PostgreSQL 16.

```bash
pnpm install
pnpm db:setup          # תפקידים dlx_owner / dlx_app ומסדי dlx + dlx_test (פעם אחת)
pnpm db:seed           # מיגרציות + עסק הדגמה
pnpm dev:api           # http://localhost:8787
pnpm dev:web           # http://localhost:5173
```

כניסה להדגמה, קוד עסק `demo`:

| משתמש | כניסה |
|---|---|
| בעלים | `owner@demo.co.il` / `demo1234` |
| מנהל סניף | `manager@demo.co.il` / `demo1234` · PIN `9999` |
| קופאית | PIN `1234` |
| מחסנאי | PIN `5555` |
| רו"ח | `cpa@demo.co.il` / `demo1234` |

## בדיקות

```bash
pnpm test        # core (יחידה) + api (אינטגרציה מול Postgres אמיתי: dlx_test נבנה מחדש בכל ריצה)
pnpm typecheck
```

בדיקות האינטגרציה מכסות את תרחישי הקבלה מהאפיון: מספור בלי כפילות במקביל (QA-01), חיוב אשראי חוזר בלי חיוב כפול (T12), מסמך שלא ניתן לשנות גם ישירות ב-DB (QA-03), הפרדה בין עסקים (T21, QA-19), עוסק פטור (QA-07), מספר הקצאה (QA-09), החזרה חלקית (T15, T16), מגבלת מזומן (T38), ספירה (T27), סגירת משמרת, שרשרת ביקורת ועוד.

## עקרונות

- **כסף:** מספר שלם באגורות. כמות: אלפיות יחידה (מוצר שקיל מדויק).
- **מקור אמת:** השרת מחשב מחיר, הנחה מותרת ומע"מ. הקופה מציגה מיד, ובסגירה השרת מחשב מחדש.
- **רשומות סופיות:** מסמכים, תנועות מלאי, יומן לקוח ויומן ביקורת הם append-only ברמת ה-DB. תיקון נעשה רק דרך מסמך מקושר.
- **Idempotency:** כל פעולה כספית או מסמך מקבלת `Idempotency-Key`. ניסיון חוזר לא יוצר כפילות.
- **כללים מתוארכים:** שיעור מע"מ, ספי חשבוניות ישראל ומגבלת מזומן נמצאים ב-`packages/core/src/rules.ts` עם תאריכי תחולה.
